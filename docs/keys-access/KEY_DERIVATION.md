# CXD90057 密钥派生体系（用户情报 + bootrom 静态分析）

> 2026-10-10。情报来源：用户提供（社区已知方法）+ `ILCE-7M4-RE/` 实测验证。
> 本文件是密钥相关的唯一权威汇总，后续逆向结果更新到这里。

## 一、用户提供的核心情报（2026-10-10）

1. **固件没法重新打包**（官方更新包路径走不通），**只能通过工程线刷入**，机身有 CRC 校验。
2. **密钥不是读出来的，是公式算出来的**：
   - **CXD90045**（α6400/α6600 代）：`密钥 = SHA256(A的32字节 + B的16字节 + 固定常量的32字节)`，
     常量位置 `FFFF5000`（bootrom 内）与 `F340F000`（芯片侧，具体外设待查）。
   - **CXD90057**（α1/A7M4 代）：固定常量表在 **`FFFFB800`**。
3. 密钥由"固定量"（bootrom 内常量表）演变而来。
4. **A7C2 破解的本质 = 解密 eMMC → 改文件 → 再加密 → 写回去**。

## 二、与 Buchanan 仓库实测的对齐（已验证）

`FFFFB800` 正是 Buchanan 说的 "key scrambling table"。CXD90057 bootrom 静态分析
（2026-10-10，本目录 `ILCE-7M4-RE/bootrom/CXD90057_Mira_0xFFFF0000.bin`）：

- `bootrom+0x6984`：**64×u32 偏移表**（全部 <0x400，63 个唯一值）——全 bootrom 扫描
  确认这是**唯一**一张此类表；
- `bootrom+0xB800–0xBC00`：1024B 高熵扰码垫（1020/1024 非零）；
- **eMMC AES-XTS 密钥 = 垫[偏移表[i]] 逐字节选出 64 字节**（前 32B 数据密钥 + 后 32B tweak 密钥）。
  boot0 与分区阶段偏移表**实测不同 → 两把密钥**（2026-10-11 逐项实算确认）：

  **① boot0 阶段**（偏移表 = bootrom `+0x6984` 原始值）——解 eMMC boot0 里的加密 eSRAM loader：

  ```
  f55e5630632db62cf13f1779ebb09139ec0291dc308a7971bdd3a0f3c4d86d52
  f5ee4a1a4ac2072a7a26d6af374bc7d27480bbf32957da4a8cf531aa8a9a8503
  ```

  **② 分区阶段**（偏移表 = eSRAM loader `+0x239b0` 值 **>>16**）——解用户分区 nflasha*，
  即 `decrypt_a7m4_emmc.py` 所用（A7M4 转储 nflasha3/7/15 解密实测通过）：

  ```
  162c2a3b4bc10da3ff437bf9699ce0957e4aec7524df1ea5bfad7458f987be01
  162c2a3b4bc10da3ff437bf9699ce09517be3b47d4942d325d2a4757ba91c330
  ```

  （注：② 的数据密钥与 tweak 密钥**前 16 字节相同**——loader 偏移表两半选中相同垫字节，
  属派生结果，非记录错误。两把均为 A7M4 bootrom 派生值；α1 bootrom 若为同一修订版则
  通用——dumpbrom 后 diff 确认）
- **bootrom 内无软件 SHA-256 常量、无 AES S-box** → 加解密/散列走 **SPACC 硬件引擎**
  （CXD90057 @ `0xF7FC0000`）。用户说的 SHA256 公式即由硬件引擎执行，所以二进制里找不到痕迹。

## 三、两层密钥体系（重要结论）

| 层 | 算法 | 密钥来源 | 状态 |
|---|---|---|---|
| **eMMC 块加密** | AES-XTS(512B/扇区, tweak=扇区号) | 垫@FFFFB800 + 偏移表@brom+0x6984，静态、无每机盐 | ✅ 已复算（A7M4）；α1 待 dumpbrom 验证 |
| **FDAT 更新包** | AES-128-ECB(key_aes) + CBC(key2) | **另一套公式**（SHA256 类，版本相关：v1=376A…，v2=4345…） | ⚠️ 实测**不是**垫选字节（pad 中无连续子串；逐字节出现位置随机） |

**推论**：改机路径（A7C2 式"解 eMMC→改→再加密→写回"）**完全不经过 FDAT 层**——
这解释了为什么社区不在乎更新包 RSA 封死：工程线/bootrom 层写入 eMMC，机身只有
**CRC 校验**（改完把 CRC 重算对齐即可），没有签名。

## 四、对 α1 的操作含义

1. α1 的 AI 移植**交付机制** = eMMC 写入（工程线/bootrom 串口引导 + fastboot 载荷），
   而不是更新包——原"签名死锁"只锁 FDAT 路径。
2. 写回前必须摸清"机身 CRC 校验"的具体位置（SDM2 分区表 CRC？WBI 镜像头？ext2 元数据？）
   ——从 dump 出的分区样本里定位，a7c2 社区对其机型的经验可参照。
3. eMMC 密钥确认流程：dumpbrom → 与 A7M4 bootrom diff →
   - 同版：上面 64B 密钥直接可用；
   - 异版：在 α1 bootrom 里重新定位偏移表（扫"64×u32 全<0x400"形态即可，脚本见
     本次分析，可固化成 `scripts/find_key_tables.py`），对 α1 垫重算。
